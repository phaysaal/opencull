Darkimiya · process sheet

How a shoot moves through the darkroom

Seven phases, in order, with the gates between them. Every one of them is a filter: nothing adds photographs, and what survives the last filter is what gets developed. Amber marks every step that spends a model call; everything else runs on this machine for nothing. Nothing anywhere in it deletes a photograph.

The flow

Every stage is a filter

Nothing in the pipeline adds photographs; every stage takes a set and hands on a smaller one. Some of those filters cost a model call per frame and some are free, so where you put the free ones decides what the paid ones cost.

What each phase reads and writes

Phase Reads Writes Cost
1 · Cull Every photograph in the folder A report of clusters and proposed keepers 1 per photograph
· Validate What the cull proposed Your keep-and-drop decisions, as a review beside the report none
2 · Assessment The selection, under the criteria you chose A shortlist: ten axes, a tier and a score per frame 1 per frame
· Rate Whatever the assessment proposed, if anything did Your tier and your marks, beside the shortlist rather than over it none
3 · Personal profile Finished photographs you choose, up to 64 A style profile, held for you rather than for a shoot 1 per example
4 · Editing suggestions The shortlist, your marks, your profile Four treatments per marked frame — standard, signature, creative, personal 1 per marked frame
5 · Development A treatment and the frame itself A bounded proof on screen; a full-size render when you ask none
6 · Fine tuning The operations a treatment compiled into An adjusted render, registered as its own version none
7 · Export Renders the manifest already knows about Copies, wherever you send them none

Specified here, not built yet

Two steps in the cull region are drawn hollow because the window cannot reach them today. They are on the page so the intended flow is legible, not to suggest they are finished.

Approve the whole cull at once

Today a proposal is taken group by group — Accept AI per cluster, or frame by frame. There is no single press that accepts every group, which is the natural thing to want when the cull was simply right.

Move the rejects to the trash

The machinery exists and is careful: it refuses any scope but the unselected frames, uses the platform’s own trash so the move is reversible, and records a batch that can be rolled back. Nothing in the window calls it yet.

Prefilter, before either paid run

A free pass of your own in front of the cull and in front of the assessment. This is the largest saving available anywhere in the pipeline, because it removes whole calls rather than making them cheaper.

Choose which axes are judged

The stance is chosen and reaches the prompt. Picking the axes, and asking for a releasable-or-not verdict, need the kernel’s typed schema, its normalizer and its validator changed together — and none of it can be shown to work without a live provider.

Fine tuning in words

Saying “warm the shadows a little” rather than moving the shadow control. The compiler already turns prose into bounded operations, so the path exists; what is missing is the asking.

The gates

A phase is closed only when it genuinely has no input. Nothing is closed to protect you from a bad photograph, and closing something always comes with the sentence that says how to open it.

Phase Open when What it says when it is shut
1 · Cull The folder is on disk The photographs folder is not on disk.
2 · Assessment A set exists to judge An assessment reads a selection, and this folder has none yet.
3 · Personal profile Always Never shut — it is yours, not this shoot's
4 · Editing suggestions Assessed, and at least one frame marked Nothing is marked as worth developing. Mark frames in the assessment first.
5 · Development Always Never gated on the AI — the calibrated baseline needs no suggestion
6 · Fine tuning A treatment exists to move Fine tuning moves the numbers a treatment compiled into, so there has to be a treatment.
7 · Export Something has been rendered There is nothing rendered to deliver yet. Develop a frame first.

How a RAW frame gets decoded

What never happens

Nothing deletes a photograph

Source photographs are opened read-only. Removing a folder removes the listing; culling only proposes.

An export never overwrites

If the name is taken the copy takes the next free one, and the page says which name it used.

The manifest only grows

Every render, certificate and delivery is appended as evidence. An earlier revision is never rewritten.

Guardrails can be read, not moved

A promise the treatment made is what verification checks. Switching one off would leave a certificate judging a claim that no longer holds.

Adjustments stay inside the bounds

The seventeen controls use the compiler's own ranges, so a value refused from a model is refused from a person.

The same inputs make the same file

Renders are content-addressed, so nothing is rendered twice and an adjusted proof never overwrites the suggested one.

Drawn from the code, not from memory: seven phases, four treatments, ten assessment axes, seventeen bounded controls, sixty-four style examples at most, proofs bounded at 1600px.
